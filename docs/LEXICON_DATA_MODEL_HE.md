# מודל נתונים למילון העברי

[English – Hebrew Lexicon Data Model](LEXICON_DATA_MODEL.md)

**סטטוס:** הצעת סכמת נתונים ראשונית. הסכמה אינה מחוברת עדיין לקוד התוסף ואינה תקן סופי.

## 1. מטרות

המילון של מְנַקֵּד לא יהיה מיפוי פשוט של מילה אחת לצורת ניקוד אחת. הוא צריך לייצג:
- כתיב עברי ללא ניקוד.
- קריאה מנוקדת אחת או יותר לאותו כתיב.
- חלק דיבר ומאפיינים דקדוקיים.
- משמעות או שימוש.
- דוגמאות משפטיות שממחישות את הקריאה.
- מקור המידע ומצב הבדיקה שלו.

## 2. עקרון מרכזי: כתיב אינו משמעות

אותו רצף אותיות יכול לייצג יותר ממילה אחת או יותר מצורה דקדוקית אחת. לכן רשומת כתיב מכילה מערך של קריאות אפשריות, ולא שדה ניקוד יחיד.

דוגמאות:
- ספר: סֵפֶר (שם עצם), סָפַר (פועל), סַפָּר (שם עצם).
- מלך: מֶלֶךְ (שם עצם), מָלַךְ (פועל).
- דרך: דֶּרֶךְ (שם עצם), דָּרַךְ (פועל).
- חדש: חָדָשׁ (שם תואר), חֹדֶשׁ (שם עצם).

הדוגמאות ממחישות את הצורך בריבוי קריאות; כל רשומה במאגר הנתונים חייבת לעבור בדיקה לשונית לפני שתשמש להכרעה אוטומטית.

## 3. שדות מוצעים

### רשומת כתיב
- `id`: מזהה יציב וייחודי.
- `surface`: הכתיב ללא ניקוד, כפי שמופיע בטקסט.
- `normalization`: מדיניות נרמול שהופעלה; אין למחוק או לשנות את הטקסט המקורי.
- `readings`: רשימת הקריאות האפשריות.

### קריאה אפשרית
- `id`: מזהה הקריאה בתוך הרשומה.
- `vocalized`: הצורה המנוקדת.
- `lemma`: צורת היסוד, אם ידועה.
- `partOfSpeech`: חלק הדיבר.
- `features`: מאפיינים דקדוקיים כגון מין, מספר, גוף, זמן, בניין ומשקל.
- `sense`: תיאור קצר של המשמעות.
- `examples`: דוגמאות הקשר, כולל משפט מקור ומשפט מנוקד.
- `reviewStatus`: מצב הבדיקה הלשונית.
- `provenance`: מקור הנתונים והערת רישוי.

## 4. כללי נתונים

1. יש לשמור Unicode ב-NFC לצורך השוואה, אך לשמור בנפרד את הטקסט המקורי המדויק לצורך שחזור.
2. אין להסיר סימני ניקוד קיימים לפני שנקבעה מדיניות מפורשת לטקסט מעורב.
3. אין להניח שכל מילה במילון היא חד-משמעית.
4. אין לבחור קריאה לפי סדר הופעתה במערך.
5. יש להבדיל בין נתון שנבדק לשונית לבין הצעה שטרם נבדקה.
6. יש לתעד מקור ורישוי לכל נתון שמגיע ממקור חיצוני.
7. יש להפריד בין מילון כללי לבין שמות פרטיים, קיצורים, ראשי תיבות ומונחים ייעודיים.

## 5. דוגמת JSON רעיונית

```json
{
  "schemaVersion": 1,
  "language": "he",
  "entries": [
    {
      "id": "he-sefer",
      "surface": "ספר",
      "readings": [
        {
          "id": "book",
          "vocalized": "סֵפֶר",
          "partOfSpeech": "noun",
          "sense": "ספר לקריאה",
          "reviewStatus": "draft"
        },
        {
          "id": "counted",
          "vocalized": "סָפַר",
          "partOfSpeech": "verb",
          "sense": "מנה פריטים",
          "reviewStatus": "draft"
        }
      ]
    }
  ]
}
```

הדוגמה סכמטית בלבד. אין להשתמש בה כמילון פרודקשן ללא השלמת מאפיינים, דוגמאות ובדיקה לשונית.

## 6. מה לא שייך למילון

המילון אינו אמור להכריע לבדו בין קריאות. ניתוח תחבירי, הקשר, ניקוד של מילים סמוכות, דירוג מועמדות ורמת ביטחון שייכים לרכיבי הניתוח וההכרעה.

כך אפשר לשפר את מנגנון ההקשר בלי לשנות את מבנה הנתונים הבסיסי.

## 7. תנאי קבלה לגרסה הראשונה

- הסכמה מאפשרת כמה קריאות לאותו כתיב.
- כל קריאה כוללת צורה מנוקדת וחלק דיבר.
- ניתן לצרף משמעות ודוגמאות.
- מצב בדיקה ומקור נתונים מפורשים.
- נתונים לא ודאיים אינם מוצגים כמאומתים.
- קיימות בדיקות תקינות לסכמה ולמזהים כפולים.
